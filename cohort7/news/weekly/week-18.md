## 이번 주 TOP 3

### 1. 에이전트에게 '문'을 열어 줄 것인가 — 승인·게이트웨이·차단 (Day 85·87·88·89)
월요일 미국 대형 은행들은 메타 '뮤즈' 같은 외부 에이전트의 계좌 접근·이체를 막고 "돈이 나갈 땐 사람이 승인"을 원칙으로 세웠다. 수요일 MS는 해킹당하지 않은 에이전트도 '에이전틱 내부자'로 보고 가디언 에이전트로 실시간 감시한다고 했고, 목요일 월마트는 아마존과 반대로 자체 MCP 서버 '에이전트 게이트웨이'를 열어 "승인된 에이전트는 들어와서 사도 된다"고 했다. 금요일 앤트로픽 '클로드 듀엣'은 6,000개 넘는 커넥터를 붙이되 결제는 사용자 승인, 이체·주식 거래는 아예 금지했다.
Ch08 **Tool/Agent** 설계의 결론은 같다. 도구를 많이 붙이는 것보다 **어떤 도구를 누가, 어떤 승인 아래 부르게 할지(최소 권한 + human-in-the-loop)**가 제품의 신뢰를 결정한다.

### 2. 공급망이 곧 공격면 — LLM 프록시·코딩 에이전트·모델 의존성 (Day 87·88·89)
목요일 인기 LLM 프록시 '라이트LLM'의 PyPI·도커 이미지에 클라우드·AI 키를 훔치는 악성코드가 심겼고, 같은 날 AI 에이전트로 기업 100여 곳을 해킹하는 데 총 약 660만 원이면 충분했다는 실험이 나왔다. 금요일 오픈코드는 API 키 유출 사고 대응 중 프런티어 모델이 분석을 거절해 대응이 막혔다. 수요일 미국의 딥시크 퇴출 명령, 금요일 딥시크의 약 150억 달러 투자 유치 보도까지 겹치며 "어떤 모델·패키지를 믿고 쓸 것인가"가 기술 선택이 아닌 리스크 관리 문제가 됐다.
Ch08에서 체인을 짤 때 **패키지 버전 고정, API 키 분리, 모델 폴백(`with_fallbacks`), 모델 추상화(`init_chat_model`)**를 처음부터 넣어야 하는 이유다.

### 3. 기억·상태·하네스 — 에이전트 품질은 '모델 밖'에서 갈린다 (Day 85·86·88·89)
GitHub 항목만 봐도 흐름이 보인다. 월 `OpenViking`(지식·기억·스킬을 파일시스템처럼 관리하는 컨텍스트 DB), 화 `ai-memory`(에이전트를 바꿔도 이어지는 장기 기억), 목 `ruflo`(100개 넘는 에이전트를 떼로 굴리는 하네스), 금 `layerfs`(에이전트별 되감기 가능한 작업 폴더)가 차례로 떴다. 목요일 UCSB·MS의 ScholarEvolve는 모델은 그대로 두고 하네스만 고쳐 성공률을 69%→81.4%로 올렸고, 금요일 티맥스티베로는 SQL+벡터 하이브리드 검색과 DB 내부 RAG를 예고했다.
Ch08의 **메모리 시스템·체크포인터·벡터DB·멀티 에이전트 오케스트레이션**이 산업의 실제 경쟁 지점이고, 그 끝에 다음 주 Ch09 **RAG(검색 파이프라인·하이브리드 검색)**가 이어진다.
