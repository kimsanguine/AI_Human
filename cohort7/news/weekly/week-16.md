## 이번 주 TOP 3

### 1. 프롬프트는 '문장'에서 '컨텍스트 설계'로 — 압축·기억·회사 용어 (Day 75·76·77·78)
월요일 `caveman`("원시인처럼 말하라" 한 줄로 코딩 에이전트 토큰 약 65% 절감), 화요일 `claude-mem`(지난 세션 기록을 다음 프롬프트에 자동 주입), 목요일 `headroom`(로그·도구 출력·검색 조각을 모델에 넣기 전 압축)까지, 이번 주 GitHub 항목은 모두 "프롬프트에 무엇을 얼마나 넣을지"를 다뤘다. 수요일 VentureBeat 조사는 회사 용어를 에이전트에 가르친 기업이 13%뿐이고 64%가 컨텍스트 부족으로 '자신만만한 오답'을 겪었다고 밝혔다.
Ch07에서 배운 Few-shot·시스템 프롬프트의 다음 단계는 **컨텍스트 엔지니어링**이다. 무엇을 기억해 넣고, 무엇을 압축하고, 어떤 사내 용어집을 붙일지가 답변 품질과 토큰 비용을 함께 결정한다. 이것이 Ch08 LangChain의 **메모리·문서 처리·검색기** 부품이 하는 일이다.

### 2. 에이전트가 '도구'에서 '동료'로 — 그리고 통제가 병목이 되다 (Day 76·77·78·79)
화요일 "평가를 통과한 AI가 고객 앞에서 사고를 냈다" 61%, 수요일 웹사이트들이 에이전트 출입을 막는 가운데 에이전트 통신 표준 착수, 목요일 위키미디어의 "오픈AI 불량 에이전트" 지적이 이어졌다. 금요일에는 구글이 자기 이메일 계정을 갖고 하위 에이전트에 일을 나누며 MCP 서버에 붙는 제미나이 에이전트를 공개했고, 국내에서는 "에이전트 사용 71%, 운영까지 11%"라는 수치와 함께 권한·감사 로그·에이전트 스프롤 문제가 제기됐다. 굿파이어는 모델 내부 활성값을 읽어 감시 비용을 $10,000에서 $51 수준으로 낮췄다.
에이전트의 능력보다 **권한 범위, 행동 기록, 사람 승인 지점, 감시 비용**이 실제 배포를 가른다. Ch08에서 Tool/Agent를 만들 때 도구마다 최소 권한과 로그를 기본으로 넣는 습관이 필요하다.

### 3. 모델은 싸지고, 고르는 기준은 '유연성'으로 (Day 75·77·78·79)
월요일 독일 알레프 알파의 '모르면 답변 보류' 오픈웨이트 모델과 리플렉션의 미국산 오픈웨이트 출시 임박, 수요일 무수비의 1.7B 정책 판정 모델, 목요일 클로드 하이쿠 5.5의 10만 토큰 미만 요청 90% 가격 인하와 누스 리서치(헤르메스 에이전트) 15억 달러 기업가치가 나왔다. 금요일 VentureBeat 조사는 기업이 에이전트 플랫폼을 고를 때 '특정 모델 때문'은 2%뿐이고, 모델·도구를 바꿔 쓸 수 있는 유연성이 1위라고 밝혔다.
작고 싼 모델, 특화 모델, 오픈 모델이 동시에 늘면서 **작업별로 모델을 갈아 끼우는 구조**가 기본이 됐다. LangChain의 모델 추상화(같은 체인, 다른 ChatModel)가 해결하는 문제가 바로 이것이다.
