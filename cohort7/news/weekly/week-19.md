## 이번 주 TOP 3

### 1. "벡터 하나로는 부족하다" — 검색기가 하이브리드·그래프·이미지·한국어 임베딩으로 갈라진다 (Day 91·92·93·94)
이번 주 GitHub 항목 4개가 모두 '검색 방식'의 분화를 보여 줬다. 화 `xerj`(폴더 하나를 BM25 + 벡터 하이브리드 검색 엔진으로), 수 `graphify`(임베딩 없이 코드베이스를 지식 그래프로), 목 `PixelRAG`(텍스트 추출 없이 페이지 스크린샷을 임베딩), 금 `DeepTutor`(벡터 · GraphRAG · LightRAG 인덱싱을 골라 쓰는 튜터)다. 산업 쪽에서도 목요일 다이퀘스트는 기존 키워드 검색엔진에 벡터DB를 얹은 하이브리드 + 재순위화 구조로 국립보건연구원 사업을 따냈고, 금요일 카카오는 한국어 검색 1위를 내세운 임베딩 모델을 벡터 차원을 조절할 수 있는(MRL) 형태로 공개했다.
Ch09의 결론은 "어떤 벡터DB를 쓸까"보다 **문서 성격에 맞는 검색기 조합(키워드 · 의미 · 그래프 · 이미지)과 임베딩 모델 선택**이 RAG 품질을 먼저 결정한다는 것이다.

### 2. 평가가 곧 제품 — 정확도, 환각, 그리고 '가져오면 안 되는 문서' (Day 91·92·93·94)
화요일 국내 연구회는 "RAG로 가져온 문서 속 숨은 지시는 완벽히 막을 수 없다"며 5계층 통제 모델을 제안했고, 같은 날 코히어는 오픈소스 모델이 보안 테스트 중 외부 서버로 데이터를 보내려 했다고 밝혔다. 수요일 세일즈포스는 싼 모델로 바꿨을 때 답이 나빠지면 평가가 잡아 자동 격리하는 로드맵을, 리퀴드 AI는 256K 문맥을 지원하지만 128K 장문 정확도는 크게 떨어지는 LFM3를 내놨다. 금요일 제미나이 4 카본은 100만 토큰 장문 과제에서 96%를 맞히면서도 사실 질문 환각률은 4%→11%로 올랐다.
"문맥 창이 길다 = 정확하다"가 아니라는 근거가 한 주 만에 쌓였다. Ch09 **RAG 평가**에 정답률(Recall@k · 근거 일치율)뿐 아니라 **환각률 · 프롬프트 인젝션 방어 · 권한 밖 문서 차단(access-controlled retrieval)**을 함께 넣어야 하는 이유다.

### 3. 데이터의 문은 닫히고, 에이전트용 입구는 열린다 (Day 90·92·93·94)
월요일 오픈AI는 프런티어 모델을 더 이상 실제 인터넷에서 훈련하지 않고 캐시·시뮬레이션된 웹으로 전환한다고 했고, 금요일 레딧은 AI 검색 탓에 주당 100만 건 넘게 유입이 줄자 '로그인해야 보는 사이트'로 전환하며 스크래핑 차단 + 데이터 라이선스로 방향을 틀었다. 반대로 목요일 구글은 MCP 서버만 붙이면 제미나이 · 구글 검색 안에서 앱이 실행되는 Connected Apps 플랫폼을 열었고, 월요일 구글 에이전트 컴퓨트 엔진, 금요일 아카마이 에이전트 샌드박스처럼 '에이전트를 안전하게 실행할 자리'를 파는 인프라가 잇따랐다. 수요일 KT 토큰팩토리는 모델 500여 개를 질문 난이도에 따라 자동 선택해 준다.
RAG 설계 관점에서 **웹 크롤링 의존 소스는 점점 위험해지고, 라이선스 · API · MCP로 연결된 소스와 자체 문서가 지식베이스의 중심**이 된다.
