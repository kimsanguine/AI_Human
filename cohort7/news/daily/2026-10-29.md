## TODAY'S TOP AI

### 1. [💻] GitHub — StarTrail-org/PixelRAG (글자를 뽑지 않고 '페이지 스크린샷'을 그대로 검색하는 비주얼 RAG)
**출처:** [GitHub — StarTrail-org/PixelRAG](https://github.com/StarTrail-org/PixelRAG) · [GitTrend RAG 트렌딩 — 2026-10-27 기준](https://gittrend.io/trending/rag)
**⭐:** 약 10.6k (GitTrend 집계, 최근 7일 +353 · 10/26~27 이틀간 약 +317)

**한 줄 설명:** "웹 파싱의 끝" — HTML·PDF를 텍스트로 바꾸지 않고, 화면 그대로 찍은 이미지 조각(타일)을 임베딩해 검색하는 RAG 시스템.

일반 RAG는 HTML을 텍스트 청크로 잘라 넣는데, 이 과정에서 표·차트·레이아웃 정보가 사라집니다. PixelRAG는 Playwright로 페이지를 스크린샷 타일로 렌더링하고, LoRA로 미세조정한 Qwen3-VL-Embedding 모델로 이미지를 벡터로 바꾼 뒤 FAISS 인덱스로 검색합니다. 파이프라인은 `render → chunk → embed → build-index → serve` 5단계로 나뉘어 있고, 위키피디아 828만 페이지를 미리 색인한 검색 API와 Claude Code 플러그인도 함께 제공합니다.

> **학습 연결:** 우리가 실습한 RAG 파이프라인의 "문서 로딩 → 청킹 → 임베딩 → 벡터 인덱스 → 검색" 단계가 그대로 있되, **청킹 단위가 '텍스트 토큰'이 아니라 '이미지 타일'**로 바뀐 구조라서 표가 많은 문서에서 텍스트 RAG가 왜 실패하는지 비교 실험하기 좋은 레퍼런스입니다.

### 2. [📰] 다이퀘스트, 국립보건연구원 'RAG 기반 의과학 지식서비스' 수주 — 기존 검색엔진은 그대로 두고 벡터DB만 얹는 하이브리드 구조
**출처:** [ZDNet Korea — 2026-10-28](https://zdnet.co.kr/view/?no=20261028175006)

다이퀘스트가 국립의과학지식센터의 키워드 검색을 AI 지식서비스로 바꾸는 사업을 따냈습니다. 자체 솔루션 'Q-RAG'는 키워드 검색과 의미 기반 검색을 합친 하이브리드 검색으로 문헌을 찾고, 결과의 연관도를 다시 평가(재순위화)한 뒤 생성형 AI에 넘겨 답변을 만듭니다. 답변 옆에 근거 문서명·페이지를 나란히 보여 주고, 의과학 특화 한국어 임베딩 모델과 로컬 LLM을 씁니다. 기관이 쓰던 검색엔진의 색인·사전에 벡터DB를 결합해 시스템 전면 교체 없이 생성형 AI를 붙이는 방식입니다.

> **학습 연결:** Ch09에서 배운 **하이브리드 검색(BM25 키워드 + 벡터 유사도) → 리랭킹 → 출처 인용 생성**의 교과서적 구성이 실제 공공 사업 요구사항으로 그대로 등장한 사례로, "도메인 특화 임베딩 모델이 왜 필요한가"를 설명할 근거가 됩니다.
