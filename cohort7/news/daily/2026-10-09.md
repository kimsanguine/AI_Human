## TODAY'S TOP AI

### 1. [💻] GitHub — langchain-ai/langchain (LLM·프롬프트·도구·메모리·검색기를 '부품'처럼 끼워 맞춰 에이전트를 만드는 오픈소스 프레임워크)
**출처:** [GitHub — langchain-ai/langchain](https://github.com/langchain-ai/langchain) · 트렌드 근거: [agents-radar AI Open Source Trends — 2026-10-08](https://github.com/yaojiejia/agents-radar/issues/263) (LLMs 부문 상위, ⭐ 147,543 · 리포트 기준)

Ch08 첫날, 이번 챕터의 주인공이 마침 이번 주 트렌딩 목록에 올라왔다. LangChain은 모델 호출, 프롬프트 템플릿, 출력 파서, 도구(tool), 메모리, 검색기(retriever)를 같은 인터페이스로 묶어 이어 붙이게 해 주는 Python 프레임워크다. OpenAI·Anthropic·Google·오픈 모델을 코드 몇 줄만 바꿔 갈아 끼울 수 있고, 같은 조직의 LangGraph(상태 기반 에이전트 그래프), LangSmith(추적·평가)와 함께 쓰인다.

> **학습 연결:** Ch07에서 손으로 짠 Few-shot·시스템 프롬프트가 LangChain에서는 `PromptTemplate → ChatModel → OutputParser`로 이어지는 **체인(Runnable 파이프라인)**의 첫 부품이 되므로, 지난주 만든 프롬프트 하나를 그대로 템플릿으로 옮겨 `prompt | llm | parser` 한 줄로 실행해 보는 것이 Ch08의 첫 실습이 된다.

### 2. [📰] 구글, 제미나이를 '동료 직원형' 에이전트로 — 자기 이메일 계정을 갖고, 하위 에이전트에 일을 나누고, MCP 서버에 연결된다
**출처:** [TechCrunch — 2026-10-08](https://techcrunch.com/2026/10/08/google-brings-agentic-ai-to-gemini-starting-with-businesses/)

구글이 클라우드 행사에서 '지시가 아닌 목표'를 받아 스스로 계획·실행하는 통합 제미나이 에이전트를 기업용으로 먼저 공개했다. 에이전트는 Workspace 계정(이메일 주소 포함)을 받아 사람처럼 태그·메일로 일을 받고, 작업을 **하위 에이전트(subagent)**에 위임하며, 스킬을 불러오고, Slack·Jira·BigQuery·Postgres 등 사내 시스템과 사내외 **MCP 서버**에 연결된다. 기본은 작업별 최적 모델 자동 선택이지만 사용자가 클로드 같은 타사 모델로 바꿀 수 있고, 모든 행동은 에이전트 명의의 감사 기록으로 남는다.

> **학습 연결:** Ch08의 **Tool/Agent 구조**(에이전트가 도구 목록을 보고 어떤 도구를 부를지 고르는 루프)와 **멀티 에이전트 위임**이 빅테크 제품에 그대로 들어간 사례로, "어떤 일을 한 에이전트에 몰고 어떤 일을 하위 에이전트로 쪼갤지"를 LangGraph 노드 설계와 비교해 볼 수 있다.

### 3. [📰] 굿파이어, 에이전트 감시를 '밖에서 읽기'에서 '안에서 들여다보기'로 — 감시 비용 $10,000 → $51
**출처:** [TechCrunch — 2026-10-08](https://techcrunch.com/2026/10/08/goodfire-says-its-new-inside-out-monitors-catch-rogue-ai-agents-at-a-fraction-of-the-cost/)

해석 가능성(interpretability) 스타트업 굿파이어가 추론 플랫폼 베이스텐 고객용 에이전트 감시 기능을 출시했다. 보통은 두 번째 AI가 에이전트의 출력을 전부 다시 읽지만, 굿파이어는 모델이 이미 계산한 **내부 활성값**에 작은 분류기(probe)를 붙여 매 단계를 검사하고, 의심될 때만 별도 AI가 정밀 검사한다. 키미 K3 약 1,500세션 기준 비용은 약 $51(최상위 모델로 매 단계 검사 시 약 $10,000)였고, 악성 해킹 세션의 94%를 잡았다.

> **학습 연결:** LangChain의 **콜백(callback)·미들웨어**로 도구 호출 직전에 검사기를 끼우는 패턴과 같은 문제("에이전트가 위험한 도구 호출을 하기 전에 어떻게 멈출까")를 다루며, 감시를 '모든 단계 LLM 재검토'로 하면 토큰 비용이 에이전트 본체보다 커질 수 있다는 설계 트레이드오프를 보여 준다.

### 4. [📰] "AI 에이전트 써 봤다 71%, 실제 운영까지 11%" — 10개 중 9개는 파일럿에서 멈춘다, 원인은 '통제'
**출처:** [ZDNet Korea — 2026-10-08](https://zdnet.co.kr/view/?no=20261008143522)

AI 페스타 2026에서 아이티센글로벌은 카문다 조사를 인용해, 에이전트를 쓰는 기업은 71%지만 지난 1년간 운영 단계까지 간 사례는 11%뿐이라고 밝혔다. 걸림돌로는 권한 관리, 행동 기록 부재, 그리고 누가 만들었는지 모르는 에이전트가 데이터 권한을 쥔 채 방치되는 **'에이전트 스프롤'**을 꼽았다. 대안으로 사용자·조직별 에이전트/데이터 권한 분리, 부서·모델별 토큰 사용량 추적, 여러 턴에 걸쳐 민감정보를 빼내는 프롬프트 인젝션 탐지, 시험 환경 검증 후 사람 승인을 거치는 배포 절차를 제시했다.

> **학습 연결:** Ch08 **메모리 시스템**(대화 이력을 다음 턴에 넘기는 구조)이 바로 "질문 하나하나는 정상인데 대화 흐름 전체로는 정보 탈취"라는 다중 턴 공격의 통로가 될 수 있으므로, 에이전트를 만들 때 도구마다 최소 권한을 주고 각 도구 호출을 로그로 남기는 것을 기본 설계에 넣어야 한다.

### 5. [📰] 기업이 에이전트 플랫폼을 고른 이유, '모델 때문'은 2%뿐 — 78%는 모델·도구 유연성, 안정성, 개발 편의, 실행 통제
**출처:** [VentureBeat — 2026-10-05](https://venturebeat.com/resources/agentic-orchestration-model-makers-are-selling-their-own-ai-agent-platforms-but-only-2-of-enterprises-say-the-model-was-the-main-reason-they-chose-one)

VentureBeat가 166개 기업을 조사한 결과, 에이전트 오케스트레이션 플랫폼 선택 이유 1위는 '여러 모델·도구를 바꿔 쓸 수 있는 유연성'(22%)이었고, 최신 모델과의 궁합을 꼽은 곳은 2%였다. 67%는 2026년 말까지 에이전트 제어 계층(control plane)이 적어도 일부는 모델 회사 밖에 있을 것으로 봤고, 23%는 에이전트 비용을 사후 로그로만 확인해 폭주하는 루프를 실시간으로 멈출 수단이 없었다. 배포된 '에이전트' 중 진짜 멀티 에이전트 워크플로가 4분의 1 이하라는 곳도 53%였다.

> **학습 연결:** LangChain이 `ChatOpenAI`·`ChatAnthropic` 등을 같은 인터페이스로 감싸는 **모델 추상화 계층**을 두는 이유가 바로 이 "모델 교체 유연성" 수요이며, 실습에서 모델 클래스 한 줄만 바꿔 같은 체인을 돌려 보면 프레임워크가 해결하는 문제를 직접 체감할 수 있다.
