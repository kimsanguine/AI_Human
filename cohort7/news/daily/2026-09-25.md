### 1. [💻] GitHub — rohitg00/ai-engineering-from-scratch (직접 만들어 보며 배우는 AI 엔지니어링 전 과정 코스)
**출처:** [GitHub — rohitg00/ai-engineering-from-scratch](https://github.com/rohitg00/ai-engineering-from-scratch) · [findarepo 집계 — 2026-09-24](https://findarepo.com/repo/rohitg00/ai-engineering-from-scratch/)
**⭐** 약 5.6만 (최근 7일 +987, findarepo 측정치) · MIT · Python

한 줄 설명: "배우고, 만들고, 남을 위해 배포하라"를 내건 **From-scratch 방식의 AI 엔지니어링 오픈 코스**.
딥러닝 기초부터 LLM, 에이전트, 배포까지를 "라이브러리를 가져다 쓰기 전에 원리를 직접 코드로 구현"하는 순서로 묶은 학습용 레포다. 2026년 3월 공개 후 반년 새 커밋 1,700여 회로 꾸준히 갱신되고 있고, 포크 비율이 스타의 약 18%로 높아 '북마크'보다 '따라 치는' 용도로 많이 쓰인다는 점이 특징이다.

> **학습 연결:** 이번 주 Ch06에서 배운 **Transformer 디코더 블록(셀프 어텐션 + 피드포워드 + 잔차 연결)**을 이 레포의 LLM 파트에서 PyTorch로 직접 쌓아 보면, `model.generate()` 한 줄 뒤에서 토큰이 한 개씩 생성되는 자기회귀 루프를 코드 단위로 확인할 수 있다.

### 2. [📰] "모델끼리 글로 대화하지 말고 KV 캐시로 대화하라" — 칭화대 'C2C', 텍스트 대비 정확도 +3~5%p·지연 최대 14배 단축
**출처:** [VentureBeat — 2026-09-22](https://venturebeat.com/orchestration/text-handoffs-slow-ai-models-down-c2c-lets-them-communicate-through-kv-caches-instead)

멀티 LLM 시스템에서 한 모델이 다른 모델에게 일을 넘길 때는 보통 텍스트 메시지를 생성해 전달한다. 칭화대 등 연구진의 **Cache-to-Cache(C2C)**는 이 대신 보내는 모델(Sharer)의 **KV 캐시를 받는 모델(Receiver)의 표현 공간으로 변환해 합치는 '캐시 퓨저'**만 학습시킨다(두 LLM은 동결). Qwen3-0.6B를 Receiver로 둔 실험에서 텍스트 전달 대비 정확도가 3.1~5.4%p 높았고, 80토큰짜리 메시지 생성에 1.3초가 걸리던 것을 약 90ms의 캐시 융합으로 대체했다. 코드는 Apache 2.0으로 공개됐지만, 모델 내부 KV 캐시에 접근 가능한 자체 추론 스택이 있어야 쓸 수 있다.

> **학습 연결:** Ch06에서 배운 **어텐션의 Key·Value 행렬과 prefill 단계에서 만들어지는 KV 캐시**가 단순한 '속도용 저장소'가 아니라 모델이 문맥을 이해한 결과 그 자체라는 점을, 서로 다른 토크나이저·층 수를 가진 모델 간 정렬 문제까지 포함해 보여주는 사례다.

### 4. [📰] 러버블(Lovable) 연환산 매출 6억 달러 돌파 — "우리는 코드가 아니라 '제품'을 출력한다"
**출처:** [TechCrunch — 2026-09-24](https://techcrunch.com/2026/09/24/lovables-annualized-revenue-crosses-600m-as-vibe-coding-takes-off/)

스웨덴 바이브 코딩 스타트업 러버블의 공동창업자 파비안 헤딘이 암스테르담 HumanX 행사에서 연환산 매출(ARR)이 6억 달러를 넘었다고 밝혔다(6월 약 5억 달러). 포춘 500 기업의 3분의 2가 사용 중이며, 사용자들이 만든 앱의 월 방문이 10억 회에 육박한다고 한다. 헤딘은 Codex·Claude Code 같은 도구와의 차이를 "코드를 내놓는 게 아니라 호스팅·배포·확장까지 붙은 제품을 내놓는 것"으로 설명했다.

> **학습 연결:** LLM의 **자연어 → 코드 생성 능력**(Ch06의 텍스트 생성 과제)이 그 자체로는 상품이 되지 못하고, 배포·호스팅 같은 '모델 밖' 레이어가 붙었을 때 매출이 된다는 점에서, 수강생 프로젝트도 모델 출력 이후의 파이프라인을 함께 설계해야 한다는 근거가 된다.
