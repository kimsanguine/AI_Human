### 1. [💻] GitHub — morluto/rea (코딩 에이전트에게 '리버스 엔지니어링 도구 상자'를 MCP로 쥐여 주는 툴킷)

"에이전트로 무엇이든 리버스 엔지니어링한다"는 TypeScript(MIT) 오픈소스로, CLI이자 MCP 서버로 동작합니다. 에이전트가 Ghidra·Hopper 같은 디컴파일러, 웹·Electron 페이지 관찰, 실행 없이 하는 바이너리 분류(triage) 같은 저수준 분석 도구를 하나의 일관된 인터페이스로 호출하고, 조사 결과를 '증거 기록'으로 남기게 해 줍니다. 4월에 만들어진 저장소가 10월 초부터 하루 수만 개씩 별을 받으며 GitTrend 전체 상위권에 올랐습니다(국내에서도 [ZDNet Korea — 2026-10-17](https://zdnet.co.kr/view/?no=20261017111354)이 소개). 소프트웨어 분석은 라이선스·법적 허용 범위 안에서만 해야 한다는 점도 함께 기억해 두세요.

> **학습 연결:** Ch08 **Tool/Agent 단원의 핵심인 "도구 스키마(이름·설명·입력 파라미터)를 정의해 LLM이 골라 호출하게 하는 구조"**가 수십 개의 전문 도구로 확장된 사례로, LangChain에서 `langchain-mcp-adapters`로 MCP 서버를 붙이면 이런 도구 묶음을 코드 수정 없이 에이전트의 `tools` 목록에 넣을 수 있다는 점을 확인해 볼 수 있습니다.

### 2. [📰] 피그마 딜런 필드, "MCP는 완벽한 프로토콜이 아니다" — 그래도 MCP 파트너 20곳 추가, "데이터를 다 열면 악용 위험도 커진다"

피그마가 인도에서 처음 연 Config 행사에서 Linear·Notion·Mistral·JetBrains Junie·메타 뮤즈 등 MCP 파트너 20곳을 새로 발표했습니다. 동시에 딜런 필드 CEO는 "MCP는 개선할 여지가 많고, 프런티어 랩에 더 유리한 구조"라며, 앤트로픽도 자사 아티팩트 등을 MCP로 다 열지 않는 '비대칭 컨텍스트 공유'를 지적했습니다. 피그마가 전부 개방하지 않는 이유로는 "MCP로 노출하는 데이터가 많을수록 악용 가능성도 커진다"는 점을 들었습니다.

### 3. [📰] MS, "해킹 안 당한 AI 에이전트도 위험하다" — 사내 에이전트를 '에이전틱 내부자'로 보고, 가디언 에이전트가 실시간 감시
**출처:** [ZDNet Korea — 2026-10-20](https://zdnet.co.kr/view/?no=20261020174529)

마이크로소프트가 기업 데이터와 시스템에 접근하는 사내 AI 에이전트를 '에이전틱 내부자'로 규정하고 새 보안 접근법을 내놨습니다. 외부 공격이 없어도 에이전트가 목표를 이루려 의도치 않은 수단을 고르는 '보상 해킹'이나 다른 에이전트와의 협업 중 생기는 위험이 있다는 이유입니다. 해법으로 7월 공개한 '프로젝트 퍼셉션'을 제시했는데, 에이전트를 식별·권한 부여 → 행동별 위험도를 동적으로 산정 → '가디언 에이전트'가 다른 에이전트를 감독하고 위험이 커지면 실시간 대응하는 3단계 구조입니다.

> **학습 연결:** LangChain 에이전트의 **실행 루프(생각 → 도구 선택 → 실행 → 관찰)를 콜백·트레이싱으로 기록하고, 위험한 도구 호출 앞에 승인 단계(human-in-the-loop)나 감시용 체인을 끼워 넣는 설계**가 기업 규모에서는 '가디언 에이전트'라는 별도 구성 요소로 발전한다는 것을 보여 줍니다.
