### 1. [💻] GitHub — JuliusBrussee/caveman ("원시인처럼 말하라"는 지시 하나로 코딩 에이전트의 토큰을 약 65% 줄이는 스킬)
**출처:** [GitHub — JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman) · 트렌드 근거: [agents-radar AI Open Source Trends — 2026-10-04](https://github.com/kouweizhu/agents-radar/issues/328) (10/4 하루 ⭐ +507)

코딩 에이전트(Claude Code, Cursor 등)에 붙여 쓰는 '스킬'입니다. 에이전트가 군더더기 없는 짧은 문장, 이른바 '원시인 말투'로 생각하고 답하게 만들어서 출력 토큰을 약 65% 줄인다고 소개됩니다.
모델을 바꾸거나 다시 학습시키지 않습니다. 말하는 방식에 대한 지시만 바꿔 비용과 속도를 개선한다는 점이 개발자들 사이에서 빠르게 퍼진 이유입니다. (레포 원문은 직접 열람하지 못했으며, 위 설명은 트렌드 리포트의 요약을 기준으로 했습니다.)

> **학습 연결:** **System Prompt의 '출력 형식·스타일 지정'** 한 줄로 답변 길이와 토큰 비용이 얼마나 달라지는지 보여 주는 사례입니다. 실습에서 같은 질문을 "자세히 설명해" 버전과 "핵심만 짧게" 버전으로 돌려 보고, 토큰 수와 정답률을 함께 비교해 보세요.

### 2. [📰] MIT·사카나AI 'SIFT' — 에이전트의 프롬프트·도구를 고칠 때마다 전부 시험하지 않고, LLM 심판이 '둘 중 어느 게 나은지'부터 고른다
**출처:** [VentureBeat — 2026-10-02](https://venturebeat.com/orchestration/new-mit-and-sakana-ai-framework-uses-an-llm-judge-to-cut-evaluation-costs-for-self-improving-coding-agents)

코딩 에이전트는 지시문(프롬프트), 도구, 코드를 고치면서 성능이 좋아집니다. 문제는 고친 버전마다 벤치마크를 돌리는 데 시간과 돈이 많이 든다는 점입니다. SIFT는 별도의 LLM 심판이 두 버전의 코드를 나란히 놓고 "어느 쪽이 더 나을지"를 먼저 판정합니다. 비싼 전체 시험은 유망한 후보에게만 돌립니다.
o3-mini 기준 Polyglot 벤치마크에서 5시간 이내, API 비용 약 150달러로 정확도 35.1%를 냈습니다(기존 DGM은 30.7%). 흥미로운 사례도 있습니다. "수정한 뒤엔 테스트를 돌려라"라는 짧은 지시를 추가한 단순한 버전이, 장치를 더 붙인 복잡한 후손 버전보다 실제 점수가 높았습니다.

> **학습 연결:** **프롬프트 설계는 '써 보고 → 평가하고 → 고치는' 반복 과정**입니다. SIFT의 'LLM-as-a-judge 쌍대 비교(A vs B)'는 우리가 프롬프트 A/B 버전을 비교할 때 바로 쓸 수 있는 평가 방법이고, "짧은 지시 하나가 복잡한 장치를 이긴" 결과는 프롬프트를 길게 쓴다고 좋아지는 게 아니라는 근거가 됩니다.

### 3. [📰] 독일 알레프 알파, 첫 오픈웨이트 모델 '콜리브리' 공개 — 모르면 지어내지 않고 "답변 보류"하도록 설계
**출처:** [AI타임스 — 2026-10-04](https://www.aitimes.com/news/articleView.html?idxno=215951)

범용 LLM 경쟁에서 물러나 방산·공공 분야로 방향을 바꾼 독일 알레프 알파가 독일어·영어 오픈웨이트 모델 '콜리브리'를 공개했습니다. 전체 781억 매개변수의 MoE 구조이고, 토큰마다 약 4.4%(34.6억 개)만 활성화합니다. 사전학습 데이터 24조 토큰 중 21.3%가 독일어입니다.
불확실한 질문에는 지어낸 답 대신 답변을 보류하도록 설계했습니다(AA-Omniscience 기준 44%). 온프레미스 구축을 지원하고, 아파치 2.0 라이선스로 허깅페이스에 공개됐습니다.

> **학습 연결:** 이 모델은 **"모르면 모른다고 답하라"는 환각 억제 지시**를 프롬프트가 아니라 학습 단계에 넣은 경우입니다. 우리가 System Prompt에 "확실하지 않으면 '확인 불가'라고 답하라"는 규칙을 쓰는 것과 같은 목표를 모델 내부에 심은 셈이라, 두 방식의 장단점(유연성 vs 일관성)을 비교해 볼 수 있습니다.

### 4. [📰] 엔비디아가 투자한 리플렉션, 미국산 고성능 오픈웨이트 모델 출시 임박 — 신세계와 '소버린 AI 팩토리' 협력도
**출처:** [Axios — 2026-10-04](https://www.axios.com/2026/10/04/reflection-open-weight-ai)

엔비디아가 투자한 스타트업 리플렉션(Reflection)이 오픈웨이트 모델 출시를 앞두고 있습니다. 처음에는 최첨단 미국 모델보다는 뒤처지고, 최상위 중국 오픈웨이트 모델과 비슷한 수준일 것으로 예상됩니다. 이달 안에 다른 서구 업체들의 오픈웨이트 모델도 잇따라 나올 전망입니다.
리플렉션의 목표는 기업이 자기 데이터와 자기 컴퓨팅으로 맞춤형 AI를 직접 만드는 'AI 팩토리'입니다. 한국 신세계그룹과 소버린 AI 팩토리 파트너십을 이미 발표했습니다.

> **학습 연결:** 오픈웨이트 모델은 Claude·GPT와 **System Prompt 준수도와 Few-shot 반응**이 다르기 때문에, 같은 프롬프트라도 모델을 바꾸면 다시 튜닝해야 합니다. "프롬프트는 모델마다 다시 검증해야 하는 자산"이라는 점을 실습 때 Ollama 로컬 모델과 상용 API에 같은 프롬프트를 넣어 비교해 보며 확인해 보세요.

### 5. [📰] 구글, 오픈소스 버그 바운티 일시 중단 — "AI가 만든 엉터리 제보가 급증해 감당 불가"
**출처:** [TechCrunch — 2026-10-04](https://techcrunch.com/2026/10/04/google-froze-its-open-source-bug-bounty-program-due-to-a-significant-rise-in-ai-submissions/)

구글이 오픈소스 소프트웨어 취약점 보상 프로그램(OSS VRP)을 10월 1일부로 멈추고, 2027년 1분기에 다시 안내하겠다고 밝혔습니다. 자동 생성된 제보가 크게 늘었는데 대부분이 유효하지 않거나 환각이 섞여 있어서, 엔지니어와 오픈소스 관리자들이 처리하지 못할 정도가 됐다는 설명입니다.
AI로 '만드는' 비용은 거의 0이 됐지만, 그것을 '검증하는' 비용은 여전히 사람이 진다는 문제를 보여 줍니다.

> **학습 연결:** **출력 검증(Self-check) 프롬프트**가 왜 필요한지 보여 주는 사례입니다. "재현 절차를 단계별로 쓰고, 각 단계에 근거 코드 줄을 인용하라" 같은 **Chain of Thought + 근거 인용 지시**를 넣으면, 근거 없는 주장을 출력 단계에서 걸러낼 수 있습니다.
