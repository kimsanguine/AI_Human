### 1. [💻] GitHub — jingyaogong/minimind (GPU 한 장으로 2시간 만에 6,400만 파라미터 LLM을 '처음부터' 학습시키는 교육용 프로젝트)
**출처:** [GitHub — jingyaogong/minimind](https://github.com/jingyaogong/minimind) · 트렌드 근거: [Trendshift 주간 트렌딩 25위 (2026-11-25 확인)](https://trendshift.io/weekly)

"Hugging Face에서 모델 받아 쓰기"가 아니라, 토크나이저 학습 → 사전학습(Pretrain) → 지도 미세조정(SFT) → 강화학습 기반 정렬까지 LLM 한 개를 만드는 전 과정을 PyTorch 코드로 직접 구현해 둔 프로젝트입니다. 약 6,400만 파라미터짜리 작은 모델을 RTX 3090 한 장으로 약 2시간 만에 학습시킬 수 있다고 소개하며, 일반 Dense 구조와 MoE(전문가 혼합) 구조를 모두 제공합니다. 다만 모델 자체는 작아서 환각이 잦고 복잡한 추론은 불안정하다는 평가가 있어, '쓰는 모델'이 아니라 '뜯어보는 교재'로 보는 것이 맞습니다.

> **학습 연결:** Ch06에서 배운 **Transformer 디코더 블록(셀프 어텐션 + FFN)** 과 Ch04의 **토크나이저 어휘 구성**을 실제 학습 루프 안에서 한 줄씩 따라가며, "사전학습과 SFT가 손실 함수·데이터 형식에서 어떻게 다른지"를 직접 확인할 수 있는 가장 짧은 경로입니다.

### 2. [📰] 앤트로픽 'Claude Ship' 공개 — 코드 리뷰·수정에 이어 '머지 승인'까지 에이전트에게
**출처:** [TechCrunch — 2026-11-23](https://techcrunch.com/2026/11/23/anthropic-launches-claude-ship-letting-ai-agents-review-fix-and-approve-code-changes/)

앤트로픽이 코드 변경을 검토·수정·승인하는 에이전트 묶음 'Claude Ship'을 내놨습니다. 이미 정식 출시된 Code Review에 더해, CI 실패·머지 충돌을 고치고 매 푸시마다 "무엇을 바꿨고 어떻게 되돌리는지"를 남기는 **PR Steward**, 그리고 팀이 저장소에 자연어로 적어 둔 승인 정책 파일에 따라 변경을 자동 승인하는 **Claude Approvals**(둘 다 베타)로 구성됩니다. 앤트로픽은 처음에는 승인 기능을 '관찰 전용 모드'로 돌리고, 저장소 하나·월 지출 한도부터 시작하라고 권합니다. GitHub 저장소 대상, Team·Enterprise 플랜에 제공됩니다.

> **학습 연결:** Ch07의 **시스템 프롬프트 설계**가 "승인 정책을 자연어 파일로 쓴다"는 형태로 제품화된 사례로, Ch08 **Tool/Agent 설계**에서 "자율 실행 → 관찰 모드 → 사람에게 에스컬레이션"이라는 단계적 권한 위임을 그대로 보여 줍니다.

**출처:** [TechCrunch — 2026-11-24](https://techcrunch.com/2026/11/24/walmart-teams-up-with-meta-to-bring-black-friday-deals-to-ai-agent-muse/)

월마트가 메타의 AI 에이전트 '뮤즈' 안에서 블랙프라이데이 상품을 찾고, 비교하고, 장바구니를 만들어 구매까지 할 수 있게 했습니다. 뮤즈가 요청을 월마트로 보내면 월마트가 상품 목록을 돌려주는 구조이며, 10월에 공개한 외부 에이전트 연결 창구 'Agent Gateway'를 통해 동작합니다. 뮤즈는 사용자의 월마트 구매 이력에 접근하지 못하고, 사용자는 지출 한도·구매 전 승인·주문 검토를 설정할 수 있습니다. 외부 에이전트 구매를 막고 있는 아마존과 뚜렷하게 대비됩니다.

### 4. [📰] SKT·KT·LG유플·네이버 "AI 에이전트가 건 고객센터 전화, 상담하지 않는다"
**출처:** [ZDNet Korea — 2026-11-24](https://zdnet.co.kr/view/?no=20261124101239)

이통 3사와 네이버가 이용자를 대신해 전화를 거는 외부 AI 에이전트(예: '피클')의 고객센터 상담을 받지 않기로 했습니다. 이유는 두 가지입니다. 통화 중 개인정보가 새거나 오남용될 수 있고, 권한을 위임받았다 해도 실제 본인이 요청했는지 확인할 방법이 없다는 것입니다. 네이버는 에이전트가 "저는 AI 에이전트입니다"라고 밝히면 상담을 진행하지 않으며, "에이전트가 사용자를 법적으로 대리할 수 있는지는 아직 논의되지 않았다"고 설명했습니다.

> **학습 연결:** 3번 월마트가 '에이전트 전용 관문'을 열었다면 국내 기업은 문을 닫은 사례로, Ch08 **에이전트 설계**에서 "누가 시킨 요청인가(인증·위임 증명)"를 도구 호출 단계에 어떻게 담을지가 기술 문제이자 제품 문제임을 보여 줍니다.

### 5. [📰] 영국 NCSC "AI 자율 해킹 도구 공격 급증 — 새 취약점이 아니라 수년간 쌓인 기술 부채가 뚫린다"
**출처:** [UK NCSC 블로그 — 2026-11-24 보도 기준](https://www.ncsc.gov.uk/blogs/familiar-weaknesses-exploited-faster-defending-against-agentic-cyber-attacks) · 보도: [TechCrunch — 2026-11-24](https://techcrunch.com/2026/11/24/uk-warns-ai-driven-cyberattacks-are-exposing-years-of-weak-security/)

영국 국가사이버보안센터(NCSC)가 9월 이후 자율형 AI 침투 테스트 도구를 악용한 공격이 "눈에 띄게 늘었다"고 경고했습니다. 공격 대상은 새로운 취약점이 아니라 외부에 노출된 시스템, 추측하기 쉬운 비밀번호, 개발자용 API 엔드포인트 같은 오래된 약점이며, 달라진 것은 이를 찾아 뚫는 '속도'라고 합니다. NCSC는 "AI가 기존 보안 통제를 쓸모없게 만들지 않는다. 기본기가 그 어느 때보다 중요하다"고 강조했습니다.

> **학습 연결:** 실습에서 만든 LangChain·RAG 앱의 **API 키 관리와 엔드포인트 노출**이 곧 공격면이라는 경고로, Ch08 **Tool/Agent** 단원에서 `.env` 분리·키 회전·호출 권한 제한을 "나중에 할 일"이 아니라 배포 전 체크리스트로 넣어야 하는 이유를 보여 줍니다.
