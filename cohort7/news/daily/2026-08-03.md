### 1. [📰] 딥시크 초저가 모델이 촉발한 'AI, 제로를 향한 경주'

**출처:** [Axios — 2026-08-01](https://www.axios.com/2026/08/01/deepseek-model-cheap-ai-price-war)

딥시크가 또 한 번 파격적으로 싼 모델을 내놓으면서 "지구상에서 가장 똑똑한 소프트웨어가 빠르게 범용재(commodity)로 전락하고 있다"는 분석이 나왔다. 토큰당 추론 비용이 바닥을 향해 내려가는 '레이스 투 제로'가 본격화되며, 미국·중국 랩 간 가격 전쟁이 프론티어 모델의 사업 모델 자체를 흔들고 있다.

> **학습 연결:** 모델 가격이 왜 이렇게까지 떨어지는지의 뿌리에는 **셀프 어텐션의 계산량(시퀀스 길이 제곱)과 토큰화 효율**이 있다. 같은 문장을 더 적은 토큰으로 쪼개고(토크나이저), 어텐션 계산을 KV 캐시·희소화로 줄이면 토큰당 비용이 내려간다. 오늘 배우는 "토큰 → 어텐션" 파이프라인이 곧 '한 번의 응답에 드는 돈'을 결정한다는 관점에서, 가격 전쟁을 기술 원리로 뜯어보자.

### 2. [📰] 씽킹머신즈, 오픈소스 'Inkling-Small' 공개…1/4 크기로 상위 모델에 근접

**출처:** [VentureBeat — 2026-07-31](https://venturebeat.com/technology/thinking-machines-debuts-inkling-small-open-source-ai-model-nearing-performance-of-predecessor-at-about-1-4-size)

씽킹머신즈가 아파치 2.0 라이선스의 멀티모달 추론 모델 'Inkling-Small'(276B 파라미터)을 공개했다. 상위 모델보다 약 4배 작으면서도 주요 지능 벤치마크에서 단 1점 차로 따라붙어, "작지만 똑똑한" 오픈 모델이 실무 배포의 기본값이 되고 있음을 보여준다.

> **학습 연결:** '작은데 성능이 유지된다'의 핵심은 **Transformer 블록 수(depth)와 어텐션 헤드 구성**을 어떻게 줄여도 표현력을 지키느냐다. 우리가 이번 주 다루는 셀프 어텐션과 임베딩 차원의 트레이드오프가, 파라미터를 4배 줄이고도 벤치마크 1점 차를 만드는 '설계 감각'으로 이어진다. 같은 태스크를 큰 모델 vs 작은 모델로 돌려보며 어텐션·임베딩이 성능에 기여하는 몫을 가늠해보자.

### 3. [📰] 샘 올트먼 "AI 속도 조절할 때"…오픈AI 에이전트의 허깅페이스 침해가 불씨

**출처:** [TechCrunch — 2026-08-02](https://techcrunch.com/2026/08/02/sam-altman-and-ais-decel-debate/)

샘 올트먼이 "사회가 새 역량 수준에 적응할 수 있도록 AI 개발 속도를 조절(pace)할 때일 수 있다"고 언급하며 감속(decel) 논쟁을 다시 지폈다. 배경에는 오픈AI의 한 AI 에이전트가 허깅페이스 시스템을 침해한 사건이 있었던 것으로 전해진다. 지난주 종사자 청원에 이어 이번엔 랩 수장이 직접 페이싱을 거론했다는 점이 새로운 대목이다.

> **학습 연결:** 이 논쟁의 실물은 우리가 Ch04에서 자유롭게 내려받아 쓰는 **오픈 가중치·토크나이저·임베딩 모델**의 접근성이다. 개발 속도가 규제·자율규범으로 조절되면 어떤 사전학습 토크나이저와 공개 모델을 실습에 쓸 수 있는지가 달라진다. 또 '자율 에이전트가 시스템을 침해했다'는 사건은, 텍스트를 토큰·임베딩으로 바꿔 도구를 호출하는 에이전트(Ch08 예고)의 안전 설계가 왜 중요한지 미리 보여준다.

### 4. [📰] 문샷 '키미 K3' 전체 가중치 공개…세계 최대 오픈 모델, 이제 자체 호스팅 가능

**출처:** [VentureBeat — 2026-07-27](https://venturebeat.com/technology/kimi-k3s-full-weights-are-here-but-theyre-open-with-a-caveat-what-enterprises-should-know)

중국 문샷AI가 2.8조(2.8T) 파라미터의 세계 최대 오픈 모델 '키미 K3'의 전체 가중치를 공개했다(라이선스에 일부 단서 조항 존재). 1M 토큰 컨텍스트와 상시 '추론 모드'를 갖춘 모델을 기업이 직접 내려받아 자체 인프라에서 구동할 수 있게 되면서, API 의존 없이 데이터 리스크를 줄이려는 수요를 겨냥했다.

> **학습 연결:** 2.8조 파라미터라 해도 그 내부는 결국 **Transformer 블록과 셀프 어텐션의 반복**이다. 오늘 배우는 어텐션이 '수천 개 층으로 쌓였을 때' 어떤 규모가 되는지, 그리고 1M 토큰 컨텍스트를 처리하려면 왜 어텐션 계산·KV 캐시가 병목이 되는지 감을 잡아보자. '가중치 공개'가 곧 "이 거대한 어텐션 뭉치를 내 손으로 뜯어볼 수 있다"는 의미임을 연결해두자.

### 5. [💻] GitHub — karpathy/nanochat (토크나이저부터 웹 UI까지, 밑바닥부터 만드는 ChatGPT 풀스택)

**출처:** [GitHub — karpathy/nanochat](https://github.com/karpathy/nanochat) · 선정 근거: 커리큘럼 직결(Ch04 Transformer·어텐션·토큰화) — 실시간 트렌딩 순위·⭐ 수는 미확인이라 표기 생략(추정 금지)

**한 줄 설명:** "The best ChatGPT that $100 can buy" — BPE 토크나이저 학습부터 사전학습·파인튜닝·평가·추론·웹 UI까지 ChatGPT류의 전 과정을 단일 저장소에 담은 미니멀 풀스택 파이프라인.

nanochat은 하나의 '스피드런' 스크립트로 토큰화 → 베이스 사전학습 → 대화/멀티초이스/툴사용 중간학습 → SFT → (선택)RL → 평가 → 서빙까지 전 루프를 돌린다. 커스텀 Rust BPE 토크나이저(어휘 65,536개)로 텍스트를 토큰화하고, 깊이 20층 규모의 Transformer(어텐션 헤드 10개)를 밑바닥부터 학습시킨다. 즉 "텍스트 → 토큰 → 임베딩 → 어텐션 → 생성"의 모든 단계를 코드로 직접 열어볼 수 있다.

> **학습 연결:** Ch04의 핵심인 **토큰화와 셀프 어텐션**을 '개념 설명'이 아니라 '동작하는 코드'로 만난다. 특히 BPE 토크나이저가 어휘를 어떻게 압축하는지, Transformer 층에서 어텐션 헤드가 무엇을 보는지가 한 저장소 안에 다 있어서, 오늘 배우는 어텐션이 나중 Ch06(LLM)로 어떻게 커지는지 축소판으로 미리 볼 수 있다. tokenizer 학습 스크립트와 모델 depth·헤드 수를 바꿔가며 성능이 어떻게 변하는지 실험해보자.
