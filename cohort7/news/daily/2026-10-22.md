### 1. [💻] GitHub — ruvnet/ruflo (Claude Code·Codex 위에 100개 넘는 전문 에이전트를 '떼(swarm)'로 굴리는 에이전트 하네스)
**출처:** [GitHub — ruvnet/ruflo](https://github.com/ruvnet/ruflo) · 트렌드 근거: [GitTrend AI Agent 트렌딩 — 2026-10-20](https://gittrend.io/trending/ai-agent) (AI Agent 부문 #6, ⭐ 약 77.9k · 최근 7일 +3.3k, [GitTrend 기준](https://gittrend.io/repo/ruvnet/ruflo))

한 줄 설명: 코딩 에이전트(Claude Code, Codex 등)를 감싸는 '실행 계층'으로, 여러 에이전트가 팀처럼 일을 나눠 하도록 조율해 주는 오픈소스 도구(MIT, TypeScript).
무엇을 하나: 요청을 받으면 **라우터**가 적절한 전문 에이전트에 일을 보내고, **스웜 매니저**가 여러 에이전트를 묶어 협업시킨다. 성공한 작업 패턴은 **메모리 저장소**에 쌓아 다음 작업에 재활용하고, 벡터 RAG로 큰 코드베이스를 검색하며, MCP 서버로 도구를 등록·실행한다. `npx ruflo init` 한 줄로 작업 폴더에 설치된다.

> **학습 연결:** LangChain에서 배우는 **라우터 체인 → 전문 에이전트 → 공유 메모리(벡터DB)** 구조를 실제 대형 오픈소스가 어떻게 구현했는지 비교해 볼 수 있다 — 특히 "에이전트 수가 늘면 누가 어떤 도구를 쓸지 정하는 라우팅 층이 핵심"이라는 점을 코드로 확인할 수 있다.

### 2. [📰] 월마트, 자체 MCP 서버 '에이전트 게이트웨이' 공개 — 아마존이 막는 사이 "승인된 AI 에이전트는 들어와서 사도 된다"
**출처:** [TechCrunch — 2026-10-21](https://techcrunch.com/2026/10/21/while-amazon-blocks-ai-agents-walmart-rolls-out-the-welcome-mat/)

월마트가 승인된 AI 에이전트가 MCP로 접속해 재고를 검색하고 고객 대신 결제까지 할 수 있는 '에이전트 게이트웨이'를 내놨다. 다음 달 나오는 '에이전트 프로필'로 고객은 에이전트마다 따로 권한을 주고, 건별 승인이나 지출 한도를 정할 수 있다. 에이전트는 결제 정보에 접근할 수 없고 필요한 정보만 받으며, 규칙을 어기면 차단된다.

> **학습 연결:** LangChain에서 **Tool을 정의할 때 입력 스키마와 권한 범위를 좁히는 설계**가 실제 상거래에서 "에이전트 전용 프로필 + 지출 한도 + 사람 승인(human-in-the-loop)"으로 구현된 사례다 — 결제 같은 되돌릴 수 없는 도구 호출 앞에 승인 단계를 넣는 패턴을 그대로 배울 수 있다.

### 3. [📰] 인기 LLM 프록시 '라이트LLM' 해킹 — PyPI·도커 이미지에 클라우드·AI 키를 훔치는 악성코드 심겨
**출처:** [TechCrunch — 2026-10-21](https://techcrunch.com/2026/10/21/the-internet-is-having-a-very-bad-cybersecurity-day/)

여러 LLM 업체로 요청을 나눠 보내는 오픈소스 프록시 LiteLLM이 공격을 받아, PyPI·Docker Hub·GHCR에 악성 버전이 올라갔다. 악성코드는 클라우드 자격 증명, 비밀번호, AI 서비스 API 키를 훔치고 원격 명령 실행까지 가능하게 했다. LiteLLM은 악성 릴리스를 지우고 설치자에게 복구 안내를 냈다. (10/13 브리프에서 소개한 레포의 후속 — 이번엔 '공급망 보안' 관점)

> **학습 연결:** LangChain 프로젝트는 `pip install` 한 줄로 **모델 연동 패키지(ChatLiteLLM 등)와 API 키를 한곳에 모으는 구조**라, 의존성 하나가 뚫리면 모든 키가 새어 나간다 — `requirements.txt` 버전 고정(pinning)과 `.env` 키 분리·주기적 교체를 실습 체크리스트에 넣어야 하는 이유다.

### 4. [📰] "모델은 그대로, 논문을 읽고 하네스만 고쳤다" — UCSB·MS의 ScholarEvolve, 큐웬 에이전트 성공률 69%→81.4%
**출처:** [VentureBeat — 2026-10-21](https://venturebeat.com/orchestration/researchers-made-ai-agents-better-by-turning-academic-papers-into-working-code-no-retraining-required)

ScholarEvolve는 에이전트가 실패한 작업을 분석한 뒤, arXiv에서 해결 기법이 담긴 논문을 찾아 에이전트의 '하네스(도구 인터페이스·컨텍스트 관리·스킬·메모리·워크플로)' 코드를 자동으로 고친다. 모델 가중치를 건드리지 않고 Qwen3.5-27B의 AppWorld 과제 완료율을 69.0%에서 81.4%로 올렸다. 다만 연구진도 검증 안 된 외부 코드를 운영 환경에 바로 넣지 말라고 권고한다.

> **학습 연결:** LangChain의 **Tool 호출 전 입력 검증, 대화 기록을 관련도·최신순으로 잘라 넣는 메모리 관리, 반복되는 도구 호출 순서를 재사용 스킬로 묶기**가 모두 '모델이 아닌 체인 설계'로 성능을 올리는 방법임을 수치로 보여준다 — 실습에서 모델을 바꾸기 전에 체인 구조부터 손봐야 하는 근거다.

### 5. [📰] AI 에이전트로 기업 100여곳 해킹… 총비용 약 660만원, 성공 1건당 약 50달러

로이터가 인용한 보안업체 노포지 조사에 따르면, 한 해커가 오픈소스 AI 문제 해결 플랫폼 '케언'에 공격을 맡겨 미국·캐나다·호주·일본 기업 웹사이트 100여곳을 침입했다. 1200곳 넘는 사이트를 노렸고, 성공까지 평균 약 23시간 취약점을 탐색했다. 에이전트는 공개 앱에서 틈을 못 찾자 노출된 관리 패널을 스스로 찾아내 침입에 성공했다.
