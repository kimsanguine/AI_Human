### 1. [💻] GitHub — BerriAI/litellm (100개 이상의 LLM API를 하나의 OpenAI 형식으로 호출하게 해 주는 'AI 게이트웨이')
**출처:** [GitHub — BerriAI/litellm](https://github.com/BerriAI/litellm) · [트렌딩 스냅샷 — 2026-10-10](https://www.trendsmcp.ai/trending/github-trending-october-10-2026)
**⭐:** 60,810 (2026-10-10 트렌딩 스냅샷 기준)

OpenAI·Anthropic·Gemini·Bedrock·Ollama 등 서로 다른 LLM API를 `completion()` 하나로 똑같이 부를 수 있게 감싸 주는 파이썬 SDK이자 프록시 서버다. 모델별 비용·사용량 추적, 예산 한도, 장애 시 다른 모델로 넘기는 폴백(fallback), 요청 라우팅을 한곳에서 관리한다. 2023년에 만들어진 레포인데 이번 주 GitHub 트렌딩 7위로 다시 올라왔다 — 에이전트가 여러 모델을 섞어 쓰는 흐름(아래 3·4번 기사)과 맞물린 결과로 보인다.

> **학습 연결:** LangChain의 `ChatModel` 추상화가 "모델을 부품처럼 교체"하는 계층이라면, LiteLLM은 그 아래 **API 호출 계층**을 통일한다 — `ChatLiteLLM`으로 붙여 라우터 에이전트는 싼 모델, 검토 에이전트는 다른 계열 모델로 나누는 실습을 바로 해볼 수 있다.

### 2. [📰] 메타, 첫 프런티어 모델 '뮤즈 원더' 공개 — 무기는 며칠·몇 주를 기억하는 '액티브 메모리'
**출처:** [TechCrunch — 2026-10-12](https://techcrunch.com/2026/10/12/meta-releases-its-first-frontier-model-muse-wonder/)

메타 초지능 연구소가 '뮤즈 원더'와 상위판 '뮤즈 원더 풀'을 내놨다. 자체 테스트 기준 Fable 5.1·GPT-6 Astra와 비슷한 벤치마크 점수이며, API 가격은 입력 100만 토큰당 4달러·출력 20달러다(원더 풀은 API 미제공, Muse Code 구독 전용). 메타가 특히 강조한 것은 사용자 정보를 오래 유지·종합하는 '액티브 메모리'로, 장기 기억 벤치마크 MemoryBench에서 Fable·Opus·Astra를 앞섰다고 밝혔다.

> **학습 연결:** Ch08의 **메모리 시스템**(대화 버퍼 → 요약 메모리 → 벡터 저장소 기반 장기 기억)을 프레임워크가 아니라 **모델 자체가 흡수**하려는 시도다 — "메모리를 LangChain에서 직접 설계할 것인가, 모델에 맡길 것인가"를 비교해 볼 사례.

### 3. [📰] 사카나 AI, 에이전트 3개를 '순서대로' 엮은 논문 심사 시스템 — 삽입한 핵심 오류 73% 적발
**출처:** [AI타임스 — 2026-10-12](https://www.aitimes.com/news/articleView.html?idxno=216163)

사카나 AI의 MLR(Multi-Layered Review)은 부록 요약 에이전트(Claude Haiku 3.5) → 선행연구 조사 에이전트(Claude Sonnet 4) → 3단계 정독 심사 에이전트로 이어지는 파이프라인이다. 논문 257편에 일부러 넣은 모순 가운데 핵심 주장 오류를 73.43%(4회 앙상블) 찾아내 기존 최고(14.81%)를 크게 앞섰고, 건당 비용은 약 0.47달러였다. 다만 실제 철회 논문에서는 탐지율이 16~26%로 떨어져, "인공 벤치마크 성능 ≠ 실전 성능"이라는 한계도 함께 보여줬다.

> **학습 연결:** 작업을 역할별 에이전트로 쪼개고 앞 단계 산출물을 다음 단계 입력으로 넘기는 **순차 체인(Sequential Chain) / 멀티 에이전트 구성**의 실전 예다 — 단계마다 모델을 다르게(싼 모델은 요약, 강한 모델은 판단) 배치한 설계를 그대로 LCEL 파이프라인으로 옮겨 볼 수 있다.

### 4. [📰] "에이전트 하나하나는 맞는데 합치면 틀린다" — 멀티 에이전트는 '사이'를 평가하라
**출처:** [VentureBeat — 2026-10-10](https://venturebeat.com/orchestration/ai-agents-can-be-unpredictable-your-control-layer-shouldnt-be)

데이터 엔지니어 슈화 쉬의 기고. 멀티 에이전트 시스템은 핸드오프 중 정보 손실, 공유 상태(shared state)의 오염, 서로 기다리는 교착(deadlock)·무한 루프, 같은 모델을 쓴 에이전트끼리 같은 실수를 강화하는 '모델 단일 경작'으로 무너진다고 진단한다. 해법으로 에이전트 간 전달을 JSON 스키마·Pydantic으로 고정하고, LangGraph로 최대 반복·타임아웃·종료 조건을 코드로 강제하며, LangSmith로 전체 실행 트레이스를 남기라고 제안한다.

> **학습 연결:** Ch08 **Tool/Agent·복합 시스템**에서 쓰는 `with_structured_output()`(Pydantic 출력 파서)과 LangGraph의 상태(State)·체크포인트가 "왜 필요한지"를 실패 유형별로 설명해 준다 — 에이전트 A의 출력을 B에 넘기기 전 스키마 검증 노드를 하나 끼워 넣는 것이 바로 실습 과제가 된다.

### 5. [📰] MS '디시전-1'·오픈AI '디시전스 API' — 에이전트의 "어떤 도구를 쓸까?" 판단만 전담하는 초고속 모델 등장
**출처:** [AI타임스 — 2026-10-10](https://www.aitimes.com/news/articleView.html?idxno=216107)

MS가 모델 선택·요청 분류·우선순위·결과 검증 같은 '정해진 선택지 중 고르기'에 특화한 디시전-1(Qwen3.5-9B 기반)을 공개했다. 문장 대신 보정된 확률 점수를 한 번의 추론으로 내놓으며, GPT-6 Sol보다 최대 35배 빠르고 입력 100만 토큰당 0.042달러(출력 무료)다. 같은 주 오픈AI도 선택지·점수만 반환하는 '디시전스 API'를 공개 베타로 풀었다. 확신도가 높으면 자동 처리하고, 애매하면 사람에게 넘기는 '제어 레이어'로 쓰라는 것이 MS의 설명이다.

> **학습 연결:** LangChain 에이전트에서 LLM이 매 스텝 하는 **도구 선택(tool routing)·라우터 체인** 판단을 별도의 작고 빠른 분류 모델로 떼어내는 흐름이다 — `RunnableBranch`의 분기 조건을 "확률 점수 ≥ 임계값"으로 두고 나머지는 Human-in-the-loop로 보내는 구조를 설계해 볼 수 있다.
